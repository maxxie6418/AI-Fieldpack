## 一、项目是什么

### 1.1 一句话

给一个主题，产出一份自包含的单文件 HTML「知识速查手册」——目标是**个人维基词条**，不是学习笔记。

### 1.2 要解决的问题

| 现象 | 根因 | 本项目怎么解 |
| --- | --- | --- |
| 同一主题、不同 AI 或不同时间，结构与视觉漂移很大，没法沉淀 | 内容与呈现揉在同一份产物里，每次都要重写结构、样式与文案 | 内容有固定的数据形态与质量下限，页面由固定渲染层生成；**结构靠契约保证，不靠提示词措辞保证** |
| 产出浅，像说明文摘要 | 只有「写详细点」这类软要求，没有可度量的下限 | 每个模块给出**必含字段**与**数量下限**（硬约束），范例只负责把「达标」具体化 |
| 模块像凑数、各模块长相雷同 | 没有组织主线，有什么信息就放什么模块；所有模块共用一个容器 | 每类骨架有**组织主线**负责筛选模块；每个模块指定**呈现原型**（结构区分，不是配色区分） |
| 不同人对「好不好」判断不一致 | 没有验收标准 | 建立可逐项检查的验收清单（见第六节） |

### 1.3 定位与边界

**做**：

- 单主题、单页、自包含
- 面向「快速系统入门 + 长期回访查阅」两个用途
- 深度对齐 `_sandbox/nutrition-atlas.html` 样本水平

**不做**：

- 不做多轮教学闭环、不做间隔复习与学习打卡（区别于参考仓库 knowledge-internalization 的教学路线）
- 不做跨页关联、不做全局术语库——组织粒度已定为「单页自包含 + 页内显式声明」，用户自行按前置 / 相关 / 跨学科索引
- 不做收纳端（101Tips）的改造——本项目只做产出端；收纳端将来跟随生成端的令牌体系
- 不做条目级增量——增量发生在**主题级**（新主题单独生成一份）

## 二、目标与场景

### 2.1 使用场景

| 场景 | 读者的状态 | 主要落在哪些模块 |
| --- | --- | --- |
| 快速系统入门一个新领域（主场景） | 零基础或只有零散印象 | 一页纸摘要、知识地图、核心理论、术语、学习路径 |
| 事后回访查阅某个概念或数值（速查场景） | 有基础，要定位一个点 | 术语卡、条目表、数据面板、判据表 |
| 作为继续学习的路线图与出口（延伸场景） | 入门完成，要知道下一步 | 学完能做什么、延伸问题、相关主题、来源 |

### 2.2 深度目标

已定实现方式为「**一份内容 + 深度标记 + 三种视图**」——同一份内容按深度标记分区，页面提供三档视图切换，不重复写三份内容。

| 档位 | 目标 | 学术映射（详见 `1011_思维方法论参照_正式稿.md`） |
| --- | --- | --- |
| 一页入门 | 能看懂整体轮廓，能与人对话 | Bloom 认知层次：理解 |
| 全面了解 | 能分清概念之间的关系与边界，能判断适用场景 | Bloom：分析 |
| 深入掌握 | 能运用、能评价、能延伸 | Bloom：评价与创造 |

三档与模块的对应关系**尚未定**（见第四节 P0-3）。

### 2.3 产出形态

- 单文件 HTML，UTF-8 无 BOM，零外部依赖（无 CDN、无外链字体、无框架）
- 双击即可打开；深浅色可切换；有检索与导航
- 中文为主，术语附英文；正文使用简体中文

## 六、验收标准（框架，待细化）

一篇生成结果合格与否，按四个维度检查。具体阈值在阶段 1.8 填实。

| 维度 | 检查什么 |
| --- | --- |
| **结构合规** | 基线层完整（头部 4–5 节、尾部 6 节、顺序正确）；节数达下限；属性触发节按属性正确落位；每节都有层归属 |
| **内容达标** | 每个模块满足必含字段；满足数量下限（条数 / 行数 / 字数）；无空壳模块；无占位文案残留 |
| **来源可靠** | 关键论断有出处；来源按分级标注；时效信息标注时点；主观评价与客观事实分开 |
| **可用性** | 单文件可用、零外部依赖；检索与导航可用；深浅色切换正常；响应式；无障碍基本项（可聚焦、可键盘操作） |

参考：现有旧提示词的验收口径为「无空壳模块、无编造、数量达标、深度 ≥2–3 句、逻辑自洽、一页纸摘要可独立阅读、HTML 完整可用」——可继承，但要补上「必含字段」与「呈现原型」两项。

## 七、风险与已知缺口

| # | 风险 / 缺口 | 说明 | 应对 |
| --- | --- | --- | --- |
| 1 | **规格与样张之间的落差** | 验收报告指出：按「生成端能据规格机械拼装」衡量，当前约 55–65%，差距集中在契约维度而非模块维度 | 阶段 1 优先做骨架规格化，它是其余子项的载体 |
| 2 | **浅显化传染** | 原型里的样例只是结构示意，若被生成端当成内容标准，会固化出浅产出 | 用必含字段 + 数量下限作硬约束；范例只作辅助 |
| 3 | **模块 ID 一号两义** | E4 与 E8、J7 与「影响与遗产」曾出现同一 ID 不同标题 | 阶段 1 建立 ID → 标题映射，禁止复用 ID 改题 |
| 4 | **索引三处硬编码** | 原型中章节索引散落在章节导航卡、顶栏、侧栏三处，改节数要同步三处 | 阶段 2.4 收敛为单一 CONFIG 自动生成 |
| 5 | **五类可能不是完整的分类空间** | 五类由 20 个候选选题实测收敛，不代表穷尽；法规标准型、人物传记型等尚无落点 | 主线机制若成立，新类型只需定义主线即可复用模块池；先在阶段 1.1 验证 |
| 6 | **通用模块无容器区分度** | 此前 68 个模块只用了四种容器（表格 / 无序列 / 有序列 / 小块） | 阶段 2.3 为每个模块指定呈现原型 |
| 7 | **深度三档与 B4 知识分层可能打架** | B4 曾自称「深度分层的主要载体」，与三档视图功能重叠 | 阶段 1.5 一并理顺，明确 B4 是内容侧、三档是视图侧 |
| 8 | 大文件不可增量维护 | 营养学样本单文件 16 万字符，无增量能力 | 接受（单页自包含是既定粒度）；靠渲染层与 CONFIG 降低维护成本 |
