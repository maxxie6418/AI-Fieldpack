## 一、这份科普是怎么组织的（叙事流程，不涉及民航知识本身）

### 1.1 总体框架：把「听课」换成「做设计」

- 全片用第二人称「你」贯穿，把观众放在**体系设计者**的位置上，而不是学习者。旁白反复用「你选择」「你规定」「你意识到」「你称之为」——每一条规则都是"你"做的决定。
- 开篇不介绍主题，而是先造一个世界：「随着你发明的机场的落成」→ 再从这个世界里推出矛盾（天上没有悬空的马路，相撞的代价远高于地面）→ 最后才给这件事起名字（空中交通管制、ATC）。
- 这个框架的效果：后面每一条规则都不是"规定如此"，而是"你为了解决前面那个问题才这么定的"。**规则因此自带理由**，观众不需要背，只需要跟着推。

### 1.2 推进流程：六段加一尾

| 段 | 时间段 | 这一段做什么 | 组织手法 |
| --- | --- | --- | --- |
| 一 立问题 | 00:00–00:43 | 造世界 → 逼出矛盾 → 命名 | 先给场景不给结论；矛盾用代价说清（「两块速度极大的大铁坨子撞成压扁的易拉罐」） |
| 二 给底座 | 00:43–01:15 | 讲清技术手段以及它的**局限** | 先划载体边界；这些限制条件后来全部变成设计理由 |

### 1.3 核心手法：每个设计都从「约束」推出来

| 先给出的约束 | 因此定下的方案 |
| --- | --- |
| 无线电传播范围有限 | 用信标台接力覆盖 → 划出管制空域 / 非管制空域 |
| 天上不能派人上去指挥 | 只能在地面管 → 控制塔建得很高，便于俯瞰整个机场 |
| 机场是飞机最密集的地区 | 机场单独设管制单位 → 塔内再分地面 / 塔台两个席位 |
| 机场内部各区域性质不同 | 以靠机坪一侧的跑道等待点为界划地面区 / 飞行区，席位与之一一对应 |
| 平行跑道多、一个人忙不过来 | 按跑道位置分东西塔台 → 只用频率区分即可，不必真建两座塔 |
| 频率上所有监听者都听得到 | 指令必须开头点名对象；说错要发 correction 当众撤回 |
| 巡航段跨度大、换频频繁 | 管制中心一整片区域共用一个频率；中心只管汇总信号再切小区域分配 |
| 天气影响大且被反复询问 | 单设只播不收的通播；字段固定循环播报；每次配一个字母代码标识版本 |
| 管制员分不清谁是谁 | 给每架飞机一个唯一名字：注册号（通航）或呼号（商业航班） |
| 用语不统一会产生歧义 | 规定什么时候该通话、按什么模板说 |
| 无线电环境噪音大、易听错 | 字母单词化、数字改读 |
| 航空业要求万无一失 | 强制复诵关键指令 |
| 历史上因用词歧义出过重大事故 | 「起飞」一词严格限定在允许起飞、取消起飞、中断起飞三种场合 |

### 1.4 案例演示段的固定四段式

进入穆拉宾机场的实际通话流程后，每到一个通话节点，都按同一个顺序讲：

1. **触发时机**——为什么此刻必须通话（滑到飞行区边境、要穿越城墙线、进入边之后……）
2. **内容格式**——该说什么，逐项列清（叫谁 / 我是谁 / 机型 / 我在哪里 / …）
3. **双方视角**——飞行员怎么发起；管制收到后往塔外看什么、要判断哪几项、能给出哪些不同答复
4. **校验方式**——这条要不要复诵；并给一个听错的例子，演示发现与纠正的闭环

同一套四段式重复了十几次，观众一旦看懂第一次，后面就能预判。

### 1.5 可信度与边界的处理

- **规则给来源**：用一起真实重大事故（大雾天、两机相撞、583 人遇难）解释「起飞」用词为何必须严格——规则不是拍脑袋。
- **引入反向声音**：「可是管制不乐意了……我怎么知道谁对谁」——用反方的抱怨把下一个需求顶出来（即飞机命名）。
- **主动声明不讲**：「在你的规划当中，暂时还不用考虑这个问题」「本视频也只讲解了一部分」——把省略的部分明说出来，而不是含糊带过。
- **承认现实困难**：讲清真实通话"只会比这更糟糕"，需要严格训练、对环节熟悉、心里有预期才能听懂。

### 1.6 节奏与语言手法

- **概念一成形就命名**，并当场给中英双写与简称（空中交通管制 / ATC、自动终端情报服务 / ATIS / 通播、区域调度 / 区调、复诵、呼号）。名字往往在功能讲完之后才出现。
- **幽默只用在门槛处**（红警梗、「双子塔多少有点不吉利」、蹩脚口音、给说错的话配一个「撤回键」），涉及安全规则的地方一句玩笑都不开。
- **首尾呼应**：开篇「随着你发明的机场的落成」，结尾「现在我不得不恭喜你发明了民航本场陆空通话」。

## 三、视频的叙述线（按出现顺序还原）

| 时间段 | 讲了什么 |
| --- | --- |
| 00:00–00:43 | **问题设定**：机场落成、飞机普及，但天上没有悬空的马路；地面小摩擦靠边停车即可，天上相撞却是「两块大铁坨子撞成压扁的易拉罐」，所以天上必须有自己的交警——空中交通管制（air traffic control，ATC） |
| 00:43–01:15 | **技术前提**：麦克斯韦（字幕误作「麦克斯韦/麦克斯韦尔」的语境是电磁波预言）→ 无线电这种远距离通讯手段诞生。选 118–137 MHz 的甚高频作载波，用调幅方式调制，理由是既能稳定穿透大气，又允许接收端一次性接收解调多个信号 |
| 01:16–01:46 | **空间切分**：无线电传播范围有限 → 在飞机常飞的航路空域用一个个信标台接力覆盖，称**管制空域**；基本没有飞机飞的空域不建信标台，称**非管制空域**，由飞行员自行保持间隔避让 |
| 01:46–02:53 | **时间切分**：飞行全流程粗略分七阶段——滑行、起飞、离场、巡航、进场、降落、滑行；除巡航外六个阶段都在机场附近，而机场是飞机最密集之处 → 把机场管制站放在一座很高的高塔上（可俯瞰整个机场），称**控制塔**；塔内管制员再分工为**地面**与**塔台** |
| 02:24–02:53 | **空间与席位的对应**：机场也分为**飞行区**与**地面区**，一般以靠近机坪一侧的跑道等待点为界；规定地面管所有地面区的飞机（机坪与滑行道上滑行的），塔台管飞行区的飞机（起飞、降落、进离场的） |
| 02:53–03:06 | **塔台的横向再分**：跑道众多时可按跑道位置把塔台工作分给两个岗位——西侧的归西塔台、东侧的归东塔台 |
| 03:06–03:55 | **澄清与纠错**：塔台并不是塔，控制塔才是塔，所有机场管制岗位都在控制塔上；东西塔台也不是建两座塔，只是**用频率区分**、人还坐在一起。新手常把 ground 与 tower 说错，只要频率对就不影响管制；且整个频率的人都听得到，于是给说错留了「撤回键」——说错后说一句 correction，再接着说正确的信息 |
| 03:55–04:26 | **区域管制**：巡航阶段设置管理很大一片区域的**管制中心**，整个中心共用一个频率（飞行员不必频繁切换频率）；中心本身不收发无线电，而是接收各航路上各信标台发来的雷达与飞机应答机信号、以及无线电通讯信号，再划分为一个个小区域，分别交给不同管制员调度——这些管制员称**区域调度**（简称区调） |
| 04:26–05:37 | **通播**：每个机场设一个循环播报天气的频率，只向外播、不能用于通话；天气有大变化才改变播报内容。为方便收听者确认自己正在听的播报有没有变过，**给每一次播报设置一个字母代码**，只要代码与之前不同就能立刻意识到信息更新了。这套播报称**自动终端情报服务**（automatic terminal information service，ATIS，中文简称通播）。通播内容为必要信息：本次通播编号、启用的跑道与对应塔台频率、风况、云况、能见度、温度、修正海压；并给出完整示例（通播 P，跑道 35 左频率 123.0、跑道 35 右频率 118.1，风向 320、风速十节、侧风五节，二风云 5200 英尺、四风云 8000 英尺，能见度大于 10 km，温度十度，修正海压 1027 百帕） |
| 05:37–05:57 | **飞行员视角的管制链**：飞行全程一次要受起飞机场的地面 → 塔台 → 航线经过的各个区域的各个区调 → 目的地机场的塔台 → 地面的管制，并在特定位置听通播。这样就保证了飞行全程只要飞机在管制空域，就一定有一个确定的管制员可以联络 |
| 06:00–07:02 | **飞机命名**：管制员听到的是七嘴八舌的动静，必须给每架飞机一个独一无二的名字。**注册号**：国家/地区前缀（如中国 B、澳大利亚 VH）+ 各国管理局分配的编号；通航小机场飞行计划不规律，用注册号当名字足够。**呼号**：商业大机场每天航线固定、管制更在意「这一趟航班」，于是用航空公司代码加公司内部分配的代码（如 CCA981 读作国航 981） |
| 07:02–08:02 | **通话规范化**：用语不规范会产生歧义（有的说「允许起飞」、有的说「等会儿起飞」、有的说「起飞吧」）→ 效仿书同文车同轨，要求按模板说。第一步先规范化**什么时候应该进行陆空通话**，并选**五边**（飞机沿跑道一侧的环形轨迹飞行，可训练起飞、爬升、转弯、平飞、下降、着陆、复飞）作为最佳起点——正式商业运行中的起降也基本依五边流程，只是可能只用其中一部分 |
| 08:02–08:41 | **通话一：地面申请**。飞行员完成检查、来到飞行区边境，第一次和地面交流，应报：我在叫谁 / 我是谁 / 我的机型 / 我在哪里 / （训练机场）带飞还是单飞 / 我的 ATIS 代码 / 我选哪条跑道 / 我想怎么离场 / 离场去哪里。示例：穆拉宾地面，EUH，赛斯纳 172，南热车坪，带飞，通播 P，跑道 35 左，三边离场到训练区 |
| 08:41–10:05 | **防混淆编码**：有人反映分不清是 UUH 还是 EA7、情报是 P 还是 B 还是 D。类比上学时报答案怕 B、D 不分就用 boy、dog 代替，在无线电这种本就不清晰、还掺杂螺旋桨噪音的环境下，要用更清晰的词代替发音容易混淆的字母数字：用 alpha 代替 A、bravo 代替 B；EUH 读作 echo uniform hotel，情报 P 读作情报「啪啪」（papa）。数字中文读音也改：一→妖、二→两、七→拐、零→洞；英语则三读 tree、四读 fer、五读 five、九读 NINER、千读 thousand、小数点读 point 或 decimal。特殊情况下不必改，如机型中的 172 仍按习惯读 172 |
| 10:05–10:44 | **中英两个版本的通话与通播示例**（中文版见上；英语版为 Robin ground, Echo uniform hotel says, … 与整段通播英语） |
| 10:44–11:55 | **现实约束**：无线电硬件与技术导致的音质短板就在此时体现——一大长串英语加上蹩脚口音其实很难听清；真实情况只会比这更糟。真正的飞行员与管制都需经过严格训练，对各个环节极为熟悉，**心里提前对听到的内容有预期才能听懂、跟上** |
| 11:55–12:15 | **管制侧的动作**：收到申请后立刻往控制塔外看，找到飞行员报告的位置；必要时用望远镜确认飞机注册号；紧接着观察他要去的跑道口，看附近是否有别的飞机会冲突；找到一条不冲突的路线，再反馈给飞行员 |
| 12:15–13:12 | **通话二：地面回复**。因为频率中所有交流，只要在该频率下监听的人都能听到，所以空管发布的任何指令都必须在开头带上**在对谁说**。格式为：对谁说 / 怎么滑行 / 跑道多少（例：EUH 沿 alpha 滑行，alpha8 外等候，跑道 35 左 / taxi via alpha hold short of alpha eight runway 35 left）。若正巧没有空闲滑行道，可以只说 hold 加呼号，或只回复一句呼号，表示收到消息但没法给路线、要求原地等待。需要为别的飞机让路时还可以说「给某机让路」 |
| 13:12–14:12 | **复诵**：航空业必须保证万无一失，所以要求飞行员把听到的关键指令重复一遍并加上自己的呼号，防止听错或没听到——称**复诵**（字幕作「附送」）。演示了一个完整闭环：飞行员把 alpha8 听漏成 alpha 外等待 → 滑错位置 → 复诵时暴露 → 管制立刻以 negative hold short of alpha eight 纠正 → 飞行员再复诵，直到完全正确为止 |
| 14:12–15:11 | **通话三：塔台申请起飞**。飞行员滑到指定等待点会遇到**城墙线**（A 形跑道等待位置标识），按规定城墙线实线向虚线一侧穿越，所以此时需向塔台申请。飞行员把频率调到对应塔台再申请。此处给出规则来源：大雾天一起事故中，一架飞机把塔台提供航路许可里的「起飞」一词理解成了允许起飞，与正在跑道上寻找查理三滑行道的飞机迎面撞上，两机共 583 人遇难，酿成史上最大空难。因此严格规定：**「起飞」一词只在允许航空器起飞、取消起飞或中断起飞时使用**，其他情况下应使用「离场」或「离地」表达起飞的概念 |
| 15:30–16:06 | **通话四：塔台放行**。判断条件是前后空域都空、跑道上没飞机、没有正在穿越跑道的飞机或其他障碍物、没有前机留下的尾流，此时才可以说「起飞」一词（clear for takeoff）；飞行员复诵「跑道 35 左允许起飞」后进跑道滑跑起飞 |
| 16:09–16:33 | **暂不能起飞时的答复**：塔台也该给答复让飞行员知道申请收到了、要原地等待——可说「跑道 35 左外等待」（hold short of runway）或「原地等待」（hold position）。明确规定**这条指令不需要飞行员复诵** |
| 16:35–16:59 | **进跑道等待**：有时是前机尾流而非后机未落导致不能起飞，就让飞机上跑道先等着，允许了立刻起飞——这个程序称**进跑道等待**（line up and wait）；飞行员照例复诵并进跑道对准中线准备 |
| 17:02–17:53 | **立即起飞**：前机已起飞、后机还没落地，出现短暂空档时，允许正在等待的飞机起飞。已进入跑道的说「立即起飞，否则脱离跑道」（take off immediately or vacate runway），还没进入跑道的说「立即起飞，否则跑道外等待」（or hold short of runway）。飞行员能起飞就复诵「立即起飞」，不能就复诵「不能立即起飞」（unable to take off immediately） |
| 17:56–18:16 | **离场**：一旦离场、出了机场管辖的管制区，若进入管制空域就要立刻接入对应区调的频率、调整应答机编号、接收区调指挥。视频此段明确略过，暂把附近当作非管制空域 |
| 18:21–19:11 | **通话五：进场**。飞机回到机场需遵循一系列标准进场程序之一，这些程序往往在特定路径点开始，飞行员需在对应路径点调到机场对应的塔台频率。这是进场时第一次和塔台对话，要求先叫一下塔台，然后汇报呼号、机型、位置、高度和最近一次听到的通播，以方便塔台观察并安排加入进近五边（例：穆拉宾塔台，EUH，赛斯纳 172，1500 英尺，通播 Quebec，inbound） |
| 19:11–19:56 | **通话六：加入五边与落地**。塔台若允许加入进近五边，会告知加入哪条边、在哪条跑道降落（join final runway 35 left），飞行员须复诵，然后继续下降进近到对应五边高度并加入对应的边；进入边后等待塔台给出降落许可，许可为「可以落地」（clear to land），同样需要复诵 |
| 19:56–20:42 | **通话七：脱离与滑入机坪**。落地后尽快脱离跑道，从虚线一侧穿越城墙线到等待点前等待；此时飞机已脱离飞行区，要切换到地面频率，申请滑入机坪时也要先叫地面（例：穆拉宾地面，EUH，等待点 alpha4，申请滑入机坪）。地面接管后引导飞机滑向机坪；路径简单时也可只给出许可，让飞行员自己滑行，飞行员简单复诵即可完成这次飞行 |
| 20:42–21:21 | **收尾**：实际民航飞行中会出现更多的通话和情况，本视频只讲解了本场飞行中最常用的那部分陆空通话，建议去搜真实 ATC 录音感受 |

## 四、还原出的体系结构

### 4.1 技术底座

| 项 | 内容 | 它带来的约束 |
| --- | --- | --- |
| 载波 | 118–137 MHz 甚高频（VHF） | 适合直射收发；传播距离有限 |
| 调制 | 调幅（AM） | 可稳定穿透大气；允许接收端一次解调多个信号 |
| 覆盖方式 | 单台覆盖不到全程，必须接力 | 覆盖边界即管制责任边界（见 3.2） |
| 音质 | 硬件与技术的音质短板 | 听清困难 → 必须用防混淆读法（3.6）并强制复诵（3.9） |
| 频道性质 | 同一频率上所有人互相可听 | 指令必须点名对象；说错需要公开撤回 |

### 4.2 空间维度：把空域切成可归属的单元

- **管制空域**：沿飞机常飞的航路空域，用一个个信标台接力覆盖出来。
- **非管制空域**：没有被管制空域覆盖到的空域，不建信标台，由飞行员自行保持间隔避让。
- 接力覆盖的边界同时是管制责任的边界：进入谁的覆盖范围就归谁联络。

### 4.3 时间维度：把飞行过程切成阶段

- 飞行全流程粗略分为七个阶段：**滑行 → 起飞 → 离场 → 巡航 → 进场 → 降落 → 滑行**（首尾同名，起飞前与落地后各一次）。
- 除巡航外的六个阶段都发生在机场附近，而机场又是飞机最密集的地区——这决定了机场必须单独设一个管制单位（控制塔），且其内部还要再分席位。

### 4.4 组织维度：谁在管、怎么分

| 单位 | 管什么 | 边界怎么定 | 备注 |
| --- | --- | --- | --- |
| 控制塔 | 机场范围内全部管制 | — | 物理上是一座很高的塔，所有机场管制岗位都在其上 |
| ├ 地面（ground） | 地面区的飞机：机坪上与滑行道上的滑行 | 机场以靠近机坪一侧的**跑道等待点**为界，一侧地面区、一侧飞行区 | |
| ├ 塔台（tower） | 飞行区的飞机：起飞、降落、进离场的 | 同上 | 跑道众多时按跑道位置再分**东西塔台**，二者只用频率区分、人坐在同一处 |
| └ 管制中心 | 巡航阶段的一大片区域 | 覆盖一片区域，全区共用一个频率 | 本身不收发无线电，而是汇集各信标台的雷达、应答机与通讯信号，再切成小区域分给各位**区域调度**（区调） |

### 4.5 命名维度：怎么称呼一架飞机

| 方案 | 构成 | 适用场合 | 理由 |
| --- | --- | --- | --- |
| 注册号 | 国家/地区前缀（中国 B、澳大利亚 VH）+ 各国管理局分配的编号 | 通航小机场 | 这类机场的飞行计划不确定、不规律，注册号足够唯一 |
| 呼号 | 航空公司代码 + 公司内部分配的代码（如 CCA981 读作国航 981） | 商业运行的大机场 | 航线每天固定，管制在意的是「这一趟航班」，而非某一架飞机 |

### 4.6 编码方案：把容易听错的东西改成不容易听错的

| 类别 | 做法 | 例子 |
| --- | --- | --- |
| 字母 | 用不易读错的单词代替单字母发音 | alpha 代 A、bravo 代 B；EUH → echo uniform hotel；通播 P → 情报「啪啪」（papa） |
| 中文数字 | 改写发音 | 一→妖、二→两、七→拐、零→洞 |
| 英文数字 | 改写发音 | 三→tree、四→fer、五→five、九→NINER、千→thousand |
| 小数 | 改写读法 | point 或 decimal |
| 例外 | 沿用习惯读法 | 机型中的 172 仍读 172 |

### 4.7 信息服务：通播（ATIS）

| 属性 | 内容 |
| --- | --- |
| 方向 | 单向——只播报，不能用于通话 |
| 形态 | 固定字段循环播报 |
| 更新触发 | 天气出现较大变化才改变内容 |
| 版本标识 | **每次播报配一个字母代码**；代码与之前不同，即表示信息已更新 |
| 固定字段 | 通播编号、启用跑道与对应塔台频率、风向与风速与侧风、云量与云高、能见度、温度、修正海压 |

### 4.8 通话流程（本场飞行，从申请到落地）

| # | 步骤 | 发起方 | 触发时机 | 内容要点 | 是否需复诵 |
| --- | --- | --- | --- | --- | --- |
| 1 | 地面申请 | 飞行员 | 抵达飞行区边境，首次与地面通话 | 叫谁 / 我是谁 / 机型 / 位置 / 带飞或单飞 / 通播代码 / 跑道 / 离场方式与去向 | 否（首报） |
| 2 | 地面回复 | 地面 | 收到申请后 | 先点名对象，再给滑行路线与目标跑道 | 是 |
| 3 | 复诵 | 飞行员 | 收到指令 | 关键指令 + 自己的呼号 | — |
| 4 | 塔台申请 | 飞行员 | 滑到等待点、要穿越城墙线进入飞行区 | 塔台名 + 呼号 + 位置 + 跑道 + 离场请求 | 否 |
| 5 | 放行 | 塔台 | 前后空域、跑道、穿越情况、尾流四项均无冲突 | 跑道 + 「可以起飞」（clear for takeoff） | 是 |
| 6 | 暂缓 | 塔台 | 暂时不能放行 | 「跑道外等待」（hold short of runway）或「原地等待」（hold position） | **否**（明确规定不需复诵） |
| 7 | 进跑道等待 | 塔台 | 因前机尾流等原因需先上跑道等 | line up and wait | 是 |
| 8 | 立即起飞 | 塔台 | 出现短暂空档 | 「立即起飞，否则脱离跑道 / 否则跑道外等待」 | 是（能或不能都要回） |
| 9 | 离场 | 飞行员 | 出了机场管辖的管制区 | 接区调频率、改应答机编号（视频略过） | — |
| 10 | 进场 | 飞行员 | 到达标准进场程序的特定路径点 | 塔台名 + 呼号 + 机型 + 位置 + 高度 + 最近一次通播 | 否 |
| 11 | 加入五边 | 塔台 | 进场通话之后 | 加入哪条边 + 在哪条跑道降落 | 是 |
| 12 | 落地许可 | 塔台 | 进入对应的边之后 | 「可以落地」（clear to land） | 是 |
| 13 | 滑入机坪 | 飞行员 → 地面 | 脱离跑道、脱离飞行区后 | 地面名 + 呼号 + 等待点 + 申请滑入机坪 | 是（简单复诵即可） |

### 4.9 纠错机制

| 机制 | 做法 | 适用 |
| --- | --- | --- |
| correction | 说错之后先在频率上声明 correction，再接着说正确信息 | 管制或飞行员任何一方说错时（因整个频率的人都听得到，等于一个公开撤回键） |
| 复诵 | 飞行员把关键指令重复一遍并附上自己呼号；管制据此判断是否听对，不对就以 negative 纠正，飞行员再复诵，直到完全正确 | 绝大多数指令 |
| 免复诵 | 明确规定某条指令不需要复诵 | 「跑道外等待」「原地等待」 |
