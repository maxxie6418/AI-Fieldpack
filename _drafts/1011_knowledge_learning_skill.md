# 知识速查手册 skill（暂名）

- 创建：2026-10-11
- 线索来源：用户 2026-10-11 提出的第一个任务，原始表述见「一、要解决的问题」
- 现有素材：`_sandbox/知识入门提示词.md`（此前使用的提示词）、`_sandbox/nutrition-atlas.html`（此前产出的页面样本）
- 参考项目：<https://github.com/LeeWBOperation/knowledge-internalization>、<https://101.861306.xyz/>（101Tips 站点）

## 一、要解决的问题

用户要快速、系统地入门某类知识时，希望一次性获得包含知识地图、核心理论、重要概念与关键词、重要历史发展节点等内容的结果，既要完整也要有一定程度的细致，最后以 HTML 页面形式呈现。

此前用提示词尝试过，但**不同 AI 的输出内容与视觉差异较大**。因此本轮的目标不是写一段更好的提示词，而是把**视觉样式与结构模板固定下来**，并对知识做类型划分，不同类型对应不同结构。

## 二、目标定位（用户已确定）

1. **用途**：个人的速查词典，相当于个人的维基百科。（用户 2026-10-11 明确）
2. **深度**：达到 `_sandbox/nutrition-atlas.html` 这种深度，但部分内容会调整；内容至少分层级，设想为「一页入门 / 全面了解 / 深入掌握」三种程度。**该分层目前只是设想，尚待确认。**
3. **与 101Tips 的关系**：101Tips 是早期想法，因太容易漂移，用户打算重新开始该项目，分两步走——先搭以 101Tips 为目的的输出 skill，但**不做绝对限制**，产物既可录入 101Tips 也可单独使用。若 101Tips 后续做了模块化拆解，则考虑先出完整单文件、录入时再做模块化改造。**用户明确表示这部分只是目标，具体细节暂不讨论。**
4. 结论：skill 的**第一版边界定为产出端**（生成 + 完整单文件呈现），收纳端（101Tips 改造）不在第一版内。

## 三、调研结论

### 3.1 现有提示词（`_sandbox/知识入门提示词.md`）

157 行，13 个内容模块：一页纸摘要、全景知识地图、核心理论与框架、关键概念与术语、历史发展脉络、重要人物与学派、思考模式与心智模型、知识分层、当前前沿与趋势、应用领域与经典案例、学习路线图、常见误区与陷阱、跨学科关联。

设计要求 13 条：单文件 HTML、内联 CSS/JS、无外部依赖、深浅色模式、固定导航 + 侧边目录、SVG 知识地图、交互式时间线、术语卡筛选、响应式、手风琴折叠、进度追踪等。另有验收标准（无空壳模块、数量达标、深度不少于 2–3 句）。

**判断**：内容维度已经相当完整，问题在于它把自己定位为「参考框架 + 鼓励灵活补充」，这正是内容漂移的来源。

### 3.2 样本页面（`_sandbox/nutrition-atlas.html`）

实测：2192 行 / 162132 字符（文件 240999 字节），13 个 `<section id="s1..s13">`，与提示词的 13 模块一一对应。零外部资源引用，2 段内联 style + 2 段内联 script，另有 221 处行内 style。

- **视觉体系**：纸面档案 / 印刷图鉴风。纸三级 `--paper #F3EEE3` / `--paper-2 #FBF8F1` / `--paper-3 #E9E2D3`；墨三级 `--ink #1A1D17` / `--ink-2 #454B3E` / `--ink-3 #6E7566`；线 `--rule rgba(26,29,23,.14)`、`--rule-2 rgba(26,29,23,.07)`；语义色 `--ok #15803D`、`--warn #B45309`、`--dis #C2410C`、`--front #B91C1C`、`--todo #7C3AED`。accent 一节一色（`--c1`–`--c13`），组件只读 `var(--accent)`，浅底与描边用 `color-mix(in oklab, var(--accent) N%, transparent)` 派生。三级字体：display 衬线 / body 无衬线 / mono 用于标签编号。
- **组件清单（实测计数）**：`.topbar`/`.brand`/`#topnav`、`.readbar`、`.side`、`.sec-head`、`.card`+`.accent-bar`(38)、`.chip.q1–q5`(168)/`.tag`(161)、`.term`(47，`data-tier` 1/2/3 各 19/14/14)+`.tierdot`+`.more`、`.tl-item`(44)+`.yr`+`data-era`、`.tblwrap`(3)、`.line.q1–q5` 知识树、`.tier`/`.lv`/`.lvl`/`.hours`(各 3)、`.myth`(15)+`.q`/`.a`、`.formula`(4)、`.fbar`+`.fbtn`（`data-v="1|2|3"`，4 条共 19 个按钮）、`.check`(4)、`.kv`(24)、`.idx`(21)、`.grid`/`.g2`/`.g3`、`.res`(12)、`.cfg`(6)、`.stage`(4)、`.legend-chip`(4)、`.hero`。
- **交互**：全部内联，零外部依赖。`window.LS` 安全存储（1746–1752 行，全包 try/catch，不可用时静默降级）、`[data-theme="dark"]` 主题切换、JS 生成顶栏导航与侧栏目录 + 滚动高亮、筛选按钮 + 关键词过滤、`.more` 折叠、勾选状态持久化、阅读进度条、SVG 放射知识地图（常量 `CX=440, CY=332, RB=176, RL=282`）。人物、心智模型、误区三处由内嵌数据数组渲染。
- **已识别的缺陷**：①221 处行内 style 硬编码颜色与间距，换主题不跟随；②地图 / 人物 / 心智模型三套 DOM 拼接各写一遍，无公共渲染函数；③索引信息在 §1 导航卡、顶栏、侧栏三处硬编码，改节数要同步三处；④localStorage 键无命名空间与版本号；⑤三级字体均未内嵌，跨机器回退差异明显；⑥无 `data-id` 唯一性校验；⑦单文件不可增量，仅 1080/640 两个断点；⑧无障碍偏弱（无 `role`/`aria`）。

**判断**：这份样本是「重型图鉴」形态——一次生成一个完整应用。它的结构设计与视觉值得继承，但它的封闭性（内容与样式揉在同一份 HTML 里）正是漂移与不可修订的根源。

### 3.4 参考仓库 knowledge-internalization

结构：README.md + 打包后的 skill 文件，内含 SKILL.md 与 references 14 篇，采用「薄入口 + 厚参考」的路由式组织。

定位是**教学流程型** skill：三阶段（教学 → 内化 → 输出），按知识四类型（概念性 / 程序性 / 事实性 / 元认知）分派不同教法，配 L1–L5 理解层次、I0–I5 内化度、铜 / 银 / 金 / 钻石四级完成度，以及教学铁律、动机管理与会话恢复协议。

**可借鉴**：知识分型的思路、reference 路由式结构、质量检查清单。
**不适用**：它是多轮对话中改变学习者行为，跨会话、重过程；本项目要的是一次性产出可长期复用的静态页面，不需要内化闭环与间隔复习部分。

## 四、关键判断（讨论中，待用户确认）

1. **症结不是提示词不够严格，而是内容与呈现被揉进同一份 HTML**。每个 AI 都要把结构、样式、文案重写一遍，漂移是必然结果。要消除漂移，知识内容必须有独立的数据形态（单一事实来源），页面由固定渲染层生成——这是结构保证，而非提示词保证。
2. **由此得到三层结构**：生成器（skill）→ 契约层（内容模型 + 设计令牌 + 组件规范）→ 收纳站（101Tips 及其他消费端）。契约层目前缺失，是本次真正要先定义的东西。
3. **视觉不另起体系**。营养学样本的暖纸风建议作为 101Tips 的第 5 套主题并入现有令牌体系，避免「生成端」与「收纳端」各自演化成两套视觉。
4. **交付形态**：用户要求先出完整单文件，因此第一版渲染产物为自包含 HTML；但其底层应是结构化数据，录入 101Tips 时由同一份数据重新渲染，而不是从 HTML 反向解析。
5. **视觉与结构的固化分三层写死**：设计令牌（颜色 / 字体 / 间距 / 圆角）→ 组件库（固定 HTML + CSS 片段，生成时是抄而不是临场设计）→ 类型骨架（每种知识类型的 section 顺序与必选组件、数量下限）。

## 五、知识分型与深度分层草案

**两根正交的轴**：

- **知识类型轴**决定「这一页该有哪些模块」。草案（粒度待定，用户倾向先粗分、后续可细化）：理论 / 学科型、技能 / 流程型、技术栈 / 工具型、行业 / 商业型、思想史 / 学派型、法规 / 标准型。
- **深度层级轴**决定「每个模块写到多细」。用户设想三档：一页入门、全面了解、深入掌握。

**待定的核心问题**：分层是做「一份内容 + 三种视图」，还是「三份自成体系的文档」。若为后者，等于把维护量与漂移风险放大三倍，与本次目标相悖；倾向前者，但需要用户确认。

## 六、对现有 13 模块的补充建议（待确认）

在原有 13 个模块之外，建议补充：

| 补充模块 | 补什么 | 解决什么问题 |
| --- | --- | --- |
| 概念依赖与学习顺序 | 概念间前置、依赖、枢纽度，直接给出「先学什么」 | 知识地图只回答「有什么」，回答不了「从哪开始」 |
| 易混淆概念辨析 | 成对概念的边界与判别标准 | 入门者最易混的点，与「常见误区」不同，后者针对外行偏见 |
| 自测题库 | 每模块 3–5 道辨析 / 边界 / 迁移题，答案默认折叠 | 检验是否真的学会 |
| 行动触发器 | 「每当 X 场景，先问自己 Y」式清单 | 把知识转成可执行动作 |
| 前置门槛清单 | 学这个领域前需具备的术语、数学、工具基础 | 跨领域入门最常卡在这里 |
| 来源与可信度分级 | 关键结论的来源类型 + 待核实标记 | 「完整且细致」必须可追溯，也便于增量更新 |
| 时效与半衰期 | 生成日期、知识截止点、领域更新速度 | 快变领域与慢变领域不能用同一时效口径 |
| 量化数据面板 | 数值型知识用表格 / 图表承载 | 数据密集领域纯文字传达效率低 |
| 中英术语对照与索引 | 英文名、缩写、别名，支持页面内检索 | 英文术语是继续检索与追源的入口 |
| 共识与争议分离 | 标注「已定论 / 仍有争论 / 纯推测」 | 防止把争议写成结论、把推测写成趋势 |
| 持续跟进渠道 | 期刊、会议、社区、权威站点 | 入门之后要知道去哪里继续 |
| 失败案例与反例 | 经典误用与反面案例 | 正例建立认知，反例界定边界 |

## 七、借鉴 101Tips 后浮现的隐藏要求（待确认）

若目标是「个人维基」，除内容深度外还有几项硬要求，需在设计契约层时一并考虑：

- 稳定锚点：每个术语有不可变 ID，页面重构后旧链接仍能命中。
- 别名与同义词：搜「维D」「维生素D」「cholecalciferol」都能命中同一条。
- 交叉引用与反向链接：A 条提到 B 条时双向可见。
- 来源与修订时间：每条可溯源，能看出多久未更新。
- 增量录入：新增一条不必重新生成整页。
