# AI Fieldpack

把 AI 使用方法论、可复用文件和标准装进一个包，带到任何环境和需求下都能直接用。

## 项目库介绍

本库按内容成熟度分为三个区，共六类可复用资产。

**成果区**——已成稳定方法或可直接取用，取走后不需要再加工：

- `handbook/` —— **手册**：把 AI 使用方法论写成可照做的步骤与判据，一个主题一份。
- `examples/` —— **范例**：一份输入配一份输出，单文件内嵌，看完即会用。
- `packs/` —— **可复用文件**，按用途分六类：
  - `prompts/` —— 提示词
  - `skills/` —— 技能包目录：每个 skill 一个文件夹，保留原目录名与 `SKILL.md` 入口
  - `standards/` —— 标准与规范：命名、格式、质量判据
  - `templates/` —— 模板：填空即用
  - `structures/` —— 结构：目录骨架、文档骨架
  - `adapters/` —— 适配：对接具体工具、平台或环境的转换层

**工作区**——未发布、持续变动，不要直接引用其中内容：

- `_drafts/` —— 讨论稿与计划：一行点子记在 `todolist.md`，按状态分组、只移动不删除；成形的构思落成单文件或同名文件夹。
- `_lab/` —— 验证记录：假设、实验与结论；正式执行的计划随文件夹搬进来。

**支撑区**：

- `_sandbox/` —— 临时收件箱（inbox）：来源不明、格式未定或尚未判断去向的内容先扔进来，尽快分流；不进版本历史。
- `_archive/` —— 只读归档：过时或被替代的成果。
- `assets/` —— 跨文档共用素材。

## 怎么用

本仓库的操作约定集中在 [AGENTS.md](AGENTS.md)：

- **硬性规则**：单一位置、定稿文件不能随意改动、`git mv`、完成即提交、隐私与密钥严禁入库、不碰未知的改动、不确定就问、联动更新自行完成、动高风险改动先问。
- **项目 SOP**：一份内容从采集、构思、验证到定稿、维护的五个阶段，每个阶段怎么做、什么条件才算过关。
- **放哪，何时搬**：各目录放什么、何时搬走，`_lab/` 的单向规则。
- **命名与查找**：全小写 `_` 连接加日期前缀，版本序号，靠搜文件名而非记路径；该约定只约束落档前的过程文件，落档后以成品自身的格式要求为准。
- **改成果区**：定稿的小修与大重构如何区分，版本号如何补记。
- **收录第三方内容**：来源与许可登记。
- **项目经验**：经验教训、补充要求与特殊情况的记录处。
